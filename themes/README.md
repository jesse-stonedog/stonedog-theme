# The public theme catalogue

Each `<slug>.theme.json` here is a theme published for anyone to use, under this
package's Apache-2.0 licence.

## The product's copy is the source of truth, not this one

Every theme lives in its own product's repository and is edited there. This
directory is a **published mirror**, kept in step by two commands each product
provides:

| Direction | What it does |
| --- | --- |
| **push** | writes the product's current theme into this directory |
| **pull** | replaces the product's copy with the one here |

Both are idempotent: run either twice and the second run reports no change.
"No change" is judged by **resolved CSS custom properties**, not by comparing
files — two token sets can differ textually and paint identically, and can match
field-by-field while one of them emits a property the other omits.

Consequently, **do not hand-edit a file here.** The next push from that product
overwrites it, and the edit is lost with no conflict to notice. Change the theme
in its own repository and push.

## What may not be published here

**Nothing derived from someone else's brand.** HopperGuard's facility themes are
generated by scraping a customer's own website (`extractThemeFromUrl`), and the
theme's name identifies that customer. Those are a third party's brand identity
and must never reach this directory — the push tooling refuses them, and that
refusal is not a formality to work around.

Everything here is a StoneDogCode product's own palette, published deliberately.

## Adding a theme

1. Pick a slug: lowercase words joined by single hyphens, e.g. `ocean-breeze`.
   It is the file name and the theme's identity across products, so it is chosen
   once and then fixed — renaming it orphans the file rather than moving it.
2. Push from the owning product.
3. Commit the result.

The format is `JsonTheme`; see the package README. Colours are 3-, 6- or 8-char
hex (8 carries alpha) or `transparent`, which means "this slot is unset" and
emits no property at all.
